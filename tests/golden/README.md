# Golden files

| File | Format | Status |
|---|---|---|
| `format2_v0.5.json` | hash format 2 (`000002…`) | **authoritative**; generated by `cargo run --bin emit_golden_format2`, append-only (regenerated in full once before the 0.5.0 release, when the entry-point kind byte was added; ids, inputs and relations were kept); checked by `tests/golden_vectors_format2.rs`, which also enforces a minimum vector and relation count; consumed unchanged by starfix-python |
| `format1_to_format2.json` | both | record of every format-1 golden or pinned value of this repository and its format-2 value (unique ids; a test with several pinned values numbers the later ones `#2`, `#3`, ...) |
| `include_metadata_v0.3.json` | hash format 1 (`000001…`) | **historical**, kept byte-identical (pinned by `tests/legacy_v0_4_freeze.rs`); every expected hash is still asserted with the legacy 0.4 mode by `tests/legacy_v0_4_golden_vectors.rs`; its inputs are re-hashed under the same ids in `format2_v0.5.json` |
| `python_literals_format1_inputs.json` | inputs + format-1 values | inputs of starfix-python's hand-coded format-1 test literals (recovered on the Python side, reproduced with starfix 0.4); re-hashed in format 2 as the `pylit_*` vectors of `format2_v0.5.json` and listed in `format1_to_format2.json` |
