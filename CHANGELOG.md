# Changelog

## Unreleased (proposed 0.5.0)

### Fixed — hashes of affected inputs change

The v0.4.0 data layout lost information for some types; these inputs previously collided or
depended on batch boundaries. The default layout is fixed (ITL-898). An input is affected iff
its type contains a Boolean, a nullable struct, or a list whose element is a nullable list or
nullable struct; **all other inputs keep their v0.4.0 hash byte for byte**. Every changed value
is recorded in `tests/golden/fixed_in_v0.5.json`; see `docs/byte-layout-spec.md`, Section 10.

- Booleans are hashed one byte per value (v0.4.0 bit-packed them per call: trailing `false`
  values were lost and the hash depended on batch boundaries).
- A nullable struct records its own validity (v0.4.0: a null struct equalled a struct with
  all-null fields, and null rows vanished under non-nullable fields).
- A list whose element is a nullable list keeps its own lengths (v0.4.0 lost them).
- A list whose element is a nullable struct records the element validity (v0.4.0: a null
  element equalled an element with all-null fields).

Whether the hash format version prefix stays `000001` or becomes `000002` is open (one line in
`src/lib.rs`).

### Added

- `HasherConfig::ordered_columns` and `HasherConfig::ordered_struct_fields`: make column order
  and struct field order (at every depth) part of the hash. Default off. Domain-separated by an
  options tag (`docs/byte-layout-spec.md`, Section 9).
- `ArrowDigester::hash_array_with_config`.
- Golden vectors `tests/golden/ordered_v0.5.json`, generated by
  `cargo run --bin emit_golden_ordered` (append-only).

### Changed (breaking)

- `HasherConfig` has new fields: exhaustive struct literals must add `..HasherConfig::default()`.
- Default-mode hashes of affected inputs change (see Fixed).
